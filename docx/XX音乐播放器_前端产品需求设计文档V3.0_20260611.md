## 一、功能变更详述

### ✅#23 猜你喜欢/漫游：单条删除 + 一键加入歌单

#### 1.1 功能背景

当前「猜你喜欢」区域的歌曲不支持手动删除不感兴趣的单条推荐，也不支持一键将歌曲加入歌单。「音乐漫游」同样缺少加入歌单的快捷操作。用户需要更精细的推荐管理能力。

#### 1.2 交互流程

##### 猜你喜欢 - 单条删除
| 步骤 | 操作 | 交互 | 跳转 | 异常 |
|------|------|------|------|------|
| 1 | 歌曲行右侧悬浮/始终显示删除按钮（×图标） | 按钮淡入显示 | - | - |
| 2 | 点击删除按钮 | 该歌曲从推荐列表移除，列表平滑收缩 | - | 列表为空时显示空态提示 |
| 3 | 删除后推荐列表更新 | 列表序号自动重排，推荐数量更新 | - | - |

##### 猜你喜欢 - 一键加入歌单
| 步骤 | 操作 | 交互 | 跳转 | 异常 |
|------|------|------|------|------|
| 1 | 歌曲行右侧显示「加入歌单」按钮（📋图标） | 按钮淡入显示 | - | - |
| 2 | 点击「加入歌单」按钮 | 弹出歌单选择弹窗（底部Sheet/居中弹窗） | - | 未创建歌单→显示"新建歌单"入口 |
| 3 | 选择目标歌单 | 歌曲添加到歌单→Toast"已添加到XX歌单" | - | 歌曲已在歌单中→Toast"歌曲已在该歌单中" |
| 4 | 点击"新建歌单" | 弹出创建歌单弹窗→创建后自动添加 | - | - |

##### 音乐漫游 - 单条删除（已有，保持不变）
- 漫游歌曲已有 `removeRoamSong` 删除功能，保持现有交互不变

##### 音乐漫游 - 一键加入歌单
| 步骤 | 操作 | 交互 | 跳转 | 异常 |
|------|------|------|------|------|
| 1 | 漫游歌曲行右侧显示「加入歌单」按钮 | 按钮淡入显示 | - | - |
| 2 | 点击「加入歌单」按钮 | 弹出歌单选择弹窗（同猜你喜欢） | - | 同上 |
| 3 | 选择目标歌单 | 歌曲添加到歌单→Toast提示 | - | 同上 |

#### 1.3 前端实现要点

| 项目 | 说明 |
|------|------|
| 新增 Store 方法 | `removeSmartRecommend(index: number)` — 从推荐列表移除单条歌曲 |
| SongRow 组件扩展 | 新增 `onDelete` 和 `onAddToPlaylist` 回调，猜你喜欢和漫游区域传入 |
| 歌单选择弹窗 | 复用 `savedPlaylists` 列表，支持选择已有歌单或新建歌单 |
| 歌单选择弹窗样式 | 桌面端居中弹窗（480px宽），移动端底部Sheet |
| 猜你喜欢删除 | 纯前端操作，不调用后端接口，删除后列表即时更新 |
| 加入歌单 | 调用现有 `addSongToPlaylist(playlistId, song)` 方法 |

#### 1.4 验收标准

| 验收项 | 通过标准 |
|--------|----------|
| 猜你喜欢单条删除 | 点击×→歌曲从列表移除→列表平滑收缩→数量更新 |
| 猜你喜欢一键加入歌单 | 点击📋→弹出歌单选择→选择后Toast提示→歌单中可见 |
| 漫游一键加入歌单 | 同上 |
| 歌单选择弹窗 | 显示所有已创建歌单+新建歌单入口 |
| 歌曲已在歌单中 | Toast提示"歌曲已在该歌单中"，不重复添加 |
| 列表全部删除后 | 显示空态引导文案 |

### ✅#24 主题换色功能（绿/蓝/黄/紫四色主题）

#### 2.1 功能背景

当前应用仅支持绿色主题（原生主题）+ 深色模式切换。用户期望更丰富的个性化体验，支持多色主题切换，切换时平滑过渡，文字颜色自适应，装饰元素随主题变化。

| 强调色 | `emerald-500` (#10b981) |
| 主文字色 | `#3a4f34`（深绿） |
| 次文字色 | `#6b7c65` |
| 卡片背景 | `rgba(255,255,255,0.85)` |
| 卡片边框 | `rgba(200,223,192,0.45)` |
| 按钮渐变 | `from-emerald-500 to-emerald-400` |
| 装饰元素 | 底部波浪纹（绿色半透明SVG） |
| 深色模式 | 现有深色方案保持不变 |

#### 2.3 主题切换交互

| 步骤 | 操作 | 交互 | 跳转 | 异常 |
|------|------|------|------|------|
| 1 | 点击设置/主题入口 | 弹出主题选择面板 | - | - |
| 2 | 展示4个主题色块 | 绿/蓝/黄/紫圆形色块，当前主题带勾选标记 | - | - |
| 3 | 点击目标主题色块 | **全页面平滑过渡**（300ms ease-in-out）→背景/文字/按钮/装饰元素同步切换 | - | - |
| 4 | 切换完成 | Toast提示"已切换至XX主题" | - | - |

**主题切换面板位置**：
- 桌面端：顶部导航栏右侧主题色圆点按钮，点击弹出下拉面板
- 移动端：设置页面内主题选择区域

#### 2.4 平滑过渡实现方案

| 项目 | 方案 |
|------|------|
| CSS 过渡 | 所有颜色属性添加 `transition: background-color 300ms ease-in-out, color 300ms ease-in-out, border-color 300ms ease-in-out, box-shadow 300ms ease-in-out` |
| 背景渐变过渡 | 使用 CSS `@property` 注册自定义属性实现渐变动画，或使用伪元素叠加淡入淡出 |
| 装饰元素切换 | 旧装饰元素 `opacity: 1→0`（300ms），新装饰元素 `opacity: 0→1`（300ms），交叉淡入淡出 |
| TailwindCSS 主题 | 通过 `themeColor` 状态动态切换 CSS 变量类名，不使用硬编码颜色 |
| 持久化 | 主题选择存入 `localStorage: music_themeColor`，页面加载时恢复 |

#### 2.5 文字适配规则

| 主题 | 浅色模式主文字 | 浅色模式次文字 | 深色模式主文字 | 深色模式次文字 |
|------|----------------|----------------|----------------|----------------|
| 绿色 | `#3a4f34` 深绿 | `#6b7c65` 灰绿 | `#e4e4e7` 浅灰 | `#a1a1aa` 中灰 |
| 蓝色 | `#1e3a5f` 深蓝 | `#5a7a9a` 灰蓝 | `#e4e4e7` 浅灰 | `#a1a1aa` 中灰 |
| 黄色 | `#5c4a1e` 深棕 | `#8a7a50` 灰棕 | `#e4e4e7` 浅灰 | `#a1a1aa` 中灰 |
| 紫色 | `#ffffff` 纯白 | `#d4c8e0` 淡紫 | `#e4e4e7` 浅灰 | `#a1a1aa` 中灰 |

**关键原则**：
- 黄色主题使用深色调文字（深棕/深灰），规避浅底色阅读吃力问题
- 紫色主题使用白色文字，搭配饱和度适中的紫底色保障阅读清晰度
- 绿色/蓝色主题使用各自深色调文字，与底色形成足够对比度
- 深色模式下所有主题统一使用浅色文字方案

#### 2.6 前端实现要点

| 项目 | 说明 |
|------|------|
| ThemeColor 类型 | 扩展 `ThemeColor = 'green' \| 'blue' \| 'yellow' \| 'purple'`（已有） |
| Store 扩展 | `setThemeColor` 方法已有，需扩展切换逻辑：更新 CSS 变量 + 切换装饰元素 |
| CSS 变量方案 | 在 `:root` 上设置 `--theme-primary`、`--theme-bg`、`--theme-text`、`--theme-text-secondary`、`--theme-border`、`--theme-card-bg` 等变量，主题切换时更新变量值 |
| 组件适配 | 所有使用硬编码 `emerald-*` 类名的组件需改为动态类名或 CSS 变量 |
| 装饰元素组件 | `DecorationElements.tsx` 根据当前主题渲染不同的装饰 SVG |
| glass-card 适配 | `.glass-card` 样式中的颜色值改为 CSS 变量引用 |
| 深色模式联动 | 主题色与深色模式独立控制，深色模式下各主题使用统一的深色底色+对应强调色 |
| 搜索建议高亮 | `highlightMatch` 函数中的高亮色需跟随主题变化 |
| 滚动条颜色 | `.scrollbar-thin` 样式需跟随主题变化 |

#### 2.7 验收标准

| 验收项 | 通过标准 |
|--------|----------|
| 主题切换 | 点击色块→全页面300ms平滑过渡→无闪烁/跳变 |
| 四色主题正确渲染 | 绿/蓝/黄/紫各主题背景/文字/按钮/边框颜色正确 |
| 文字可读性 | 各主题浅色/深色模式下文字清晰可读，对比度≥4.5:1 |
| 蓝色主题装饰 | 页面底部可见半透明白色波浪纹，有浮动动画 |
| 黄色主题装饰 | 页面右下角可见深色小鸡图案，有浮动动画 |
| 紫色主题装饰 | 页面右下角可见白色薰衣草元素，有浮动动画 |
| 绿色主题装饰 | 保持现有装饰元素不变 |
| 主题持久化 | 刷新页面后主题保持不变 |
| 深色模式联动 | 各主题在深色模式下渲染正确 |
| 移动端适配 | 主题切换面板在移动端正常显示和操作 |

### ✅#25 虚拟验证码交互重构

#### 3.1 功能背景

当前虚拟验证码直接显示在验证码输入栏中（`value={verificationCode}`），用户无需手动输入即可直接点击登录，失去了验证码的验证意义。需要重构交互流程：验证码在页面顶端弹出展示，用户需手动填写或通过自动填写按钮填入。

#### 3.2 交互流程

##### 验证码登录模式
| 步骤 | 操作 | 交互 | 跳转 | 异常 |
|------|------|------|------|------|
| 1 | 输入手机号 | 11位数字，实时校验 | - | 格式错误→红框提示 |
| 2 | 点击「获取验证码」 | **页面顶端弹出验证码通知条**（含6位数字验证码）→按钮变为60s倒计时 | - | 60s内不可重发 |
| 3a | 手动输入验证码 | 验证码输入栏为空，用户根据顶端通知条手动输入6位数字 | - | 验证码错误→红框提示 |
| 3b | 点击「自动填写」按钮 | 验证码输入栏右侧出现「自动填写」按钮→点击后自动将顶端弹出的验证码填入输入栏 | - | 验证码已过期→提示"验证码已过期，请重新获取" |
| 4 | 点击登录 | 校验验证码正确性 | 首页 | 验证码错误→提示 |

##### 注册模式
| 步骤 | 操作 | 交互 | 跳转 | 异常 |
|------|------|------|------|------|
| 1 | 输入手机号 | 11位数字 | - | 格式错误→红框提示 |
| 2 | 点击「获取验证码」 | **页面顶端弹出验证码通知条**→60s倒计时 | - | 手机号已注册→提示 |
| 3a | 手动输入验证码 | 输入栏为空，用户手动输入 | - | 验证码错误→提示 |
| 3b | 点击「自动填写」 | 自动填入顶端弹出的验证码 | - | 验证码已过期→提示 |
| 4 | 设置密码+确认密码 | 8-16位字母数字组合 | - | 不符合规则→提示 |
| 5 | 点击注册 | 校验通过→注册成功 | 首页 | - |

##### 重置密码模式
| 步骤 | 操作 | 交互 | 跳转 | 异常 |
|------|------|------|------|------|
| 1 | 输入手机号 | 11位数字 | - | 手机号未注册→提示 |
| 2 | 点击「获取验证码」 | **页面顶端弹出验证码通知条**→60s倒计时 | - | - |
| 3a | 手动输入验证码 | 输入栏为空，用户手动输入 | - | 验证码错误→提示 |
| 3b | 点击「自动填写」 | 自动填入顶端弹出的验证码 | - | 验证码已过期→提示 |
| 4 | 设置新密码+确认新密码 | 8-16位字母数字组合 | - | 不符合规则→提示 |
| 5 | 点击重置密码 | 校验通过→重置成功 | 登录表单 | - |

#### 3.3 验证码顶端通知条设计

| 属性 | 说明 |
|------|------|
| 位置 | 页面最顶端，固定定位 `fixed top-0`，z-index: 100 |
| 样式 | 圆角底部卡片，半透明毛玻璃效果，宽度 max-w-sm 居中 |
| 内容 | 图标 + "验证码：" + **6位大号加粗数字** + 关闭按钮 |
| 动画 | 从顶部滑入（slideDown 300ms），5分钟后自动消失或点击关闭 |
| 验证码显示 | 6位数字，每位间距4px，等宽字体，字号20px，加粗 |
| 主题适配 | 跟随当前主题色渲染 |

**通知条示意**：
```
┌─────────────────────────────────────────┐
│  📱 验证码： 8 4 7 2 9 1          ✕    │
└─────────────────────────────────────────┘
```

#### 3.4 验证码输入栏「自动填写」按钮

| 属性 | 说明 |

**输入栏示意**：
```
┌──────────────────┐ ┌──────────┐ ┌──────────┐
│  请输入验证码     │ │ 获取验证码 │ │ 自动填写  │
└──────────────────┘ └──────────┘ └──────────┘
```

#### 3.5 前端实现要点

| 项目 | 说明 |
|------|------|
| 验证码状态管理 | `verificationCode` 状态保持不变，但不再绑定到输入框的 `value` |
| 新增输入状态 | 新增 `codeInput` 状态，作为验证码输入框的实际值（用户手动输入或自动填写） |
| 顶端通知条组件 | 新增 `VerificationCodeBanner` 组件，接收验证码值和关闭回调 |
| 自动填写按钮 | 验证码输入栏右侧新增按钮，点击时 `setCodeInput(verificationCode)` |
| 倒计时逻辑 | 点击「获取验证码」后按钮变为60s倒计时，倒计时结束恢复可点击 |
| 验证码过期 | 验证码5分钟有效，过期后顶端通知条自动消失，自动填写按钮隐藏 |
| 登录/注册/重置 | 三种模式均使用相同的验证码交互逻辑 |
| 验证码校验 | 提交时比较 `codeInput` 与 `verificationCode` 是否一致 |

#### 3.6 验收标准

| 验收项 | 通过标准 |
|--------|----------|
| 验证码不自动填入 | 点击获取验证码后，输入栏为空，不显示验证码 |
| 顶端通知条 | 验证码在页面顶端弹出显示，6位数字清晰可见 |
| 手动输入 | 用户可根据顶端通知条手动输入验证码并登录 |
| 自动填写 | 点击「自动填写」按钮→验证码自动填入输入栏 |
| 验证码过期 | 5分钟后通知条消失，自动填写按钮隐藏 |
| 注册模式 | 注册流程验证码交互与登录一致 |
| 重置密码模式 | 重置密码流程验证码交互与登录一致 |
| 倒计时 | 获取验证码后60s倒计时，期间不可重复获取 |
| 主题适配 | 通知条样式跟随当前主题色 |
