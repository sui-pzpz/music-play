## 二、代码命名规范

### 2.1 通用原则

- 名称应清晰表达含义，避免模糊不清
- 优先使用英文单词，选择广泛认可的术语（如ID、URL、HTTP等）
- 避免使用缩写词，除非是约定俗成的
- 名称应包含足够信息，不误导开发者

### 2.2 变量命名

- 使用 **camelCase**（小驼峰命名）

```
userName
orderList
totalPrice
isActive
```

### 2.3 常量命名

- 使用 **UPPER_SNAKE_CASE**（全大写+下划线）

```
MAX_RETRY_COUNT
DEFAULT_TIMEOUT
API_BASE_URL
```

### 2.4 函数/方法命名

- 使用 **camelCase**（小驼峰命名）
- 动词开头，清晰表达动作意图

```
getUserInfo()
calculateTotal()
isValid()
onButtonClick()
```

### 2.5 类/接口命名

- 使用 **PascalCase**（大驼峰命名）

```
UserService
OrderController
HttpResponse
IRepository（接口以 I 开头）
```

### 2.6 文件/模块命名

- 使用 **kebab-case**（连字符分隔）

```
user-service.ts
order-controller.js
api-utils.py
```

### 2.7 数据库命名

- 表名使用 **snake_case**（小写+下划线），采用复数形式
- 字段名使用 **snake_case**（小写+下划线）

```
表名：user_accounts, order_items
字段名：user_name, created_at, is_active
```

## 三、Git 分支与提交信息规范

### 3.1 分支命名

格式：`{类型}/{描述}`

| 类型 | 说明 | 示例 |
|------|------|------|
| feature | 新功能 | feature/user-login |
| fix | 修复缺陷 | fix/payment-error |
| refactor | 重构 | refactor/order-module |
| docs | 文档 | docs/api-guide |
| release | 发布 | release/v1.2.0 |

### 3.2 提交信息

格式：`{类型}: {简要描述}`

```
feat: 添加用户登录功能
fix: 修复支付回调问题
refactor: 重构订单模块
docs: 更新接口文档
```

## 四、项目命名规范

- 项目名使用 **kebab-case**（全小写）
- 目录/文件夹使用 **kebab-case** 或 **snake_case**

```
my-project
order-service
user-management
```
