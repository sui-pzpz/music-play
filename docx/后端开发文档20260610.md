## 文档说明

### 编写目的

本文档基于《后端产品需求设计文档 V2.0》编写，将后端开发任务拆分为**数据库设计**、**客户端API接口**和**管理平台**三大部分，为后端开发提供明确的开发指引。

### 重要约定

> **⚠️ 禁止修改前端代码**：本项目前端已有完整实现（React + TypeScript + Vite），后端开发过程中**不得修改** **`src/`** **目录下的任何前端文件**。后端代码独立于前端代码之外。

## 第一部分：数据库设计

### 1.1 数据库概览

基于 V2.0 数据模型，共 **19 张表**，覆盖用户、音乐、歌单、收藏、会员、通知等核心业务。

```
数据库名：music_platform
字符集：utf8mb4
排序规则：utf8mb4_unicode_ci
```

### 1.2 核心业务表

#### 1.2.1 用户表（t\_user）

用户核心信息，含安全字段（登录失败次数、锁定时间）。

```sql
CREATE TABLE t_user (
    id              BIGINT       PRIMARY KEY AUTO_INCREMENT,
    uid             VARCHAR(20)  NOT NULL UNIQUE            COMMENT '用户唯一标识',
    phone           VARCHAR(11)  NOT NULL UNIQUE            COMMENT '手机号(AES加密)',
    password        VARCHAR(60)  NOT NULL                   COMMENT 'BCrypt加密密码',
    nickname        VARCHAR(20)  NOT NULL                   COMMENT '昵称',
    avatar          VARCHAR(255) DEFAULT NULL               COMMENT '头像URL',
    gender          TINYINT      DEFAULT 0                  COMMENT '0未知/1男/2女',
    birthday        DATE         DEFAULT NULL               COMMENT '生日',
    signature       VARCHAR(100) DEFAULT NULL               COMMENT '个性签名',
    status          TINYINT      DEFAULT 1                  COMMENT '0禁用/1正常',
    login_fail_count INT         DEFAULT 0                  COMMENT '连续登录失败次数',
    lock_until      DATETIME     DEFAULT NULL               COMMENT '锁定截止时间',
    last_login_at   DATETIME     DEFAULT NULL               COMMENT '最后登录时间',
    last_login_ip   VARCHAR(45)  DEFAULT NULL               COMMENT '最后登录IP',
    created_at      DATETIME     NOT NULL                   COMMENT '创建时间',
    updated_at      DATETIME     NOT NULL                   COMMENT '更新时间',
    deleted_at      DATETIME     DEFAULT NULL               COMMENT '软删除时间',
    INDEX idx_status (status),
    INDEX idx_deleted_at (deleted_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

#### 1.2.2 歌曲表（t\_song）

歌曲元数据，含音质标识、播放计数等。`default_artist_id` 为冗余字段，用于列表快速展示主歌手。

```sql
CREATE TABLE t_song (
    id                BIGINT       PRIMARY KEY AUTO_INCREMENT,
    song_id           VARCHAR(20)  NOT NULL UNIQUE           COMMENT '歌曲唯一标识',
    name              VARCHAR(100) NOT NULL                  COMMENT '歌曲名称',
    default_artist_id BIGINT       DEFAULT NULL              COMMENT '默认主歌手ID(冗余)',
    album_id          BIGINT       DEFAULT NULL              COMMENT '专辑ID',
    duration          INT          DEFAULT NULL              COMMENT '时长(秒)',
    is_vip            TINYINT      DEFAULT 0                 COMMENT '0免费/1付费',
    has_standard      TINYINT      DEFAULT 1                 COMMENT '有标准音质',
    has_high          TINYINT      DEFAULT 1                 COMMENT '有高清音质',
    has_lossless      TINYINT      DEFAULT 0                 COMMENT '有无损音质',
    lyric_url         VARCHAR(255) DEFAULT NULL              COMMENT '歌词文件URL',
    tlyric_url        VARCHAR(255) DEFAULT NULL              COMMENT '翻译歌词URL',
    play_count        BIGINT       DEFAULT 0                 COMMENT '播放次数',
    status            TINYINT      DEFAULT 1                 COMMENT '0下架/1正常',
    source            VARCHAR(20)  DEFAULT NULL              COMMENT '来源(netease/qq/local)',
    source_id         VARCHAR(50)  DEFAULT NULL              COMMENT '来源平台ID',
    created_at        DATETIME     NOT NULL                  COMMENT '创建时间',
    updated_at        DATETIME     NOT NULL                  COMMENT '更新时间',
    INDEX idx_name (name),
    INDEX idx_default_artist (default_artist_id),
    INDEX idx_album (album_id),
    INDEX idx_is_vip (is_vip),
    INDEX idx_play_count (play_count),
    INDEX idx_status (status),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='歌曲表';
```

#### 1.2.3 歌手表（t\_artist）

```sql
    created_at   DATETIME     NOT NULL             COMMENT '创建时间',

```

#### 1.2.4 歌曲-歌手关联表（t\_song\_artist）

支持多歌手（主唱/feat/制作人），一对多关系。

```sql
CREATE TABLE t_song_artist (

    UNIQUE KEY uk_song_artist_role (song_id, artist_id, role)
```


#### 1.2.6 歌单表（t\_playlist）

用户创建或官方歌单，支持软删除。


#### 1.2.7 歌单歌曲关联表（t\_playlist\_song）

歌单与歌曲的多对多关联，含排序字段。外键使用自增 BIGINT，业务查询时 JOIN 获取业务ID。

```sql
CREATE TABLE t_playlist_song (

```

#### 1.2.8 收藏表（t\_collection）

统一收藏表，`target_type` 区分"喜欢歌曲"(song)和"收藏歌单"(playlist)。

```sql
CREATE TABLE t_collection (
    id          BIGINT      PRIMARY KEY AUTO_INCREMENT,
    uid         VARCHAR(20) NOT NULL          COMMENT '用户UID',
    target_type VARCHAR(20) NOT NULL          COMMENT 'song(喜欢)/playlist(收藏歌单)',
    target_id   VARCHAR(20) NOT NULL          COMMENT '目标ID',
    created_at  DATETIME    NOT NULL          COMMENT '收藏时间',
    INDEX idx_uid (uid),
    UNIQUE KEY uk_uid_target (uid, target_type, target_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='收藏表';
```

> 喜欢歌曲上限 10000 首（业务层校验）。

#### 1.2.9 播放历史表（t\_play\_history）

记录用户播放行为，定时任务保证每用户最多 100 条。

```sql
CREATE TABLE t_play_history (

    quality     VARCHAR(20) DEFAULT NULL      COMMENT '音质',

    source_id   VARCHAR(20) DEFAULT NULL      COMMENT '来源ID',

    INDEX idx_uid_time (uid, played_at DESC),

```

## 第三部分：管理平台

### 3.1 概述

管理平台是面向运营人员的后台管理系统，提供用户管理和歌曲管理功能。管理平台作为单体项目中的一个独立模块（`admin` 模块），通过独立的接口路径前缀 `/api/v1/admin/` 与前端交互，不依赖主项目前端代码。

管理平台前端使用 Vue 3 + Element Plus 开发，构建产物部署在 `backend/src/main/resources/static/admin/` 目录下，通过 `http://localhost:8080/admin/` 访问。

### 3.2 管理平台技术选型

| 组件 | 技术                          | 版本         | 说明       |
| -- | --------------------------- | ---------- | -------- |
| 框架 | Spring Boot 3.x + Java 17 | 与主项目一致   |
| 前端 | Vue 3 + Element Plus + TypeScript | 独立于主项目前端，已实现 |
| 鉴权 | JWT + 管理员角色                 | 独立 Token |
| 部署 | 前端构建产物放在 `static/admin/` | 通过路径前缀区分 |

> 管理平台的前端页面使用通用的后台管理模板开发，**与主项目的前端代码完全独立**，不修改 `src/` 下的任何文件。

### 3.3 管理员账号体系

#### 4.2.3 安装 MySQL 8.4

```powershell
winget install Oracle.MySQL --accept-source-agreements --accept-package-agreements
```

安装完成后需手动初始化（**以管理员身份运行 PowerShell**）：

```powershell
cd "C:\Program Files\MySQL\MySQL Server 8.4\bin"

# 1. 初始化数据目录（记录输出的临时密码）
.\mysqld.exe --initialize --console

# 2. 注册为 Windows 服务
.\mysqld.exe --install MySQL84

# 3. 启动 MySQL 服务
net start MySQL84

# 4. 用临时密码登录并修改密码
.\mysql.exe -u root -p
```

在 MySQL 命令行中修改密码：

```sql
ALTER USER 'root'@'localhost' IDENTIFIED BY 'root';
FLUSH PRIVILEGES;
EXIT;
```

**各步骤详解：**

**步骤 1 — `mysqld --initialize --console`**

MySQL 安装后只有程序文件，没有数据存储目录。这一步做了什么：
- 在 `C:\Program Files\MySQL\MySQL Server 8.4\` 下创建 `data` 文件夹
- 在 `data` 里生成系统必需的文件：
  - `ibdata1` — InnoDB 存储引擎的核心数据文件
  - `ib_logfile0`、`ib_logfile1` — 事务日志文件
  - `mysql/` — 系统数据库（存储用户权限、系统配置等）
  - `performance_schema/` — 性能监控数据库
- 自动生成一个**临时 root 密码**，显示在输出中（如 `[Note] A temporary password is generated for root@localhost: c+esNCtfW86o`）

> 为什么需要临时密码？MySQL 默认不允许空密码登录，必须先用临时密码登录再改密码。

**步骤 2 — `mysqld --install MySQL84`**

把 MySQL 注册到 Windows 服务管理器（`services.msc`）：
- 之后可以用 `net start MySQL84` / `net stop MySQL84` 控制启停
- 设置为"自动"则开机自启，"手动"则需要手动启动
- 如果不注册为服务，每次开机都要手动运行 `mysqld.exe`

**步骤 3 — `net start MySQL84`**

启动 MySQL 服务，之后用临时密码登录并修改密码。

**步骤 4 — 修改密码**

```sql
ALTER USER 'root'@'localhost' IDENTIFIED BY 'root';  -- 改密码为 root
FLUSH PRIVILEGES;   -- 刷新权限，让修改立即生效
EXIT;
```

### 4.3 初始化数据库

在 MySQL 安装目录下执行（管理员 PowerShell）：

```powershell
cd "C:\Program Files\MySQL\MySQL Server 8.4\bin"

# 1. 创建数据库
.\mysql.exe -u root -proot -e "CREATE DATABASE IF NOT EXISTS music_platform DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 2. 建表（执行 init.sql）
.\mysql.exe -u root -proot music_platform -e "source C:/Users/z1306/Documents/trae_projects/music-play/music-play/backend/sql/init.sql"

# 3. 初始化管理员数据
.\mysql.exe -u root -proot music_platform -e "source C:/Users/z1306/Documents/trae_projects/music-play/music-play/backend/sql/admin-init.sql"

# 4. 验证（应看到 20 张表和管理员数据）
.\mysql.exe -u root -proot -e "USE music_platform; SHOW TABLES;"
.\mysql.exe -u root -proot -e "USE music_platform; SELECT admin_name, role FROM t_admin;"
```

> **注意**：SQL 文件路径中使用正斜杠 `/`，不要用反斜杠 `\`。

**各步骤详解：**

**步骤 1 — 创建数据库**

```sql
CREATE DATABASE IF NOT EXISTS music_platform
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_unicode_ci;
```

- 创建一个名为 `music_platform` 的数据库（如果不存在）
- 字符集设为 `utf8mb4`，支持中文和 Emoji 表情
- 排序规则设为 `utf8mb4_unicode_ci`，中文排序更准确

**步骤 2 — 建表（执行 `init.sql`）**

`init.sql` 里是一系列 `CREATE TABLE` 语句，定义了 20 张业务表的结构，例如：

```sql
CREATE TABLE t_user (
    id         BIGINT PRIMARY KEY AUTO_INCREMENT,  -- 自增主键
    uid        VARCHAR(20) NOT NULL UNIQUE,         -- 业务唯一标识
    phone      VARCHAR(11) NOT NULL UNIQUE,         -- 手机号（AES加密）
    password   VARCHAR(60) NOT NULL,                -- BCrypt加密密码
    nickname   VARCHAR(20) NOT NULL,                -- 昵称
    status     TINYINT DEFAULT 1,                   -- 0禁用/1正常
    created_at DATETIME NOT NULL,                   -- 创建时间
    ...
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

执行后数据库里就有了 20 张**空表**，就像建好了 20 个空的 Excel 表格，有表头但没有数据。

**步骤 3 — 插入管理员数据（执行 `admin-init.sql`）**

`admin-init.sql` 里是 `INSERT INTO` 语句，插入两个管理员账号：

```sql
INSERT INTO t_admin (username, password, nickname, role, ...) VALUES
('admin',    '$2a$10$N9qo8u...', '超级管理员', 'super_admin', ...),
('operator', '$2a$10$N9qo8u...', '运营管理员', 'admin',       ...);
```

- 密码是 **BCrypt 加密**后的密文，原文是 `admin123`
- `admin` 是超级管理员，拥有所有权限
- `operator` 是普通管理员，权限受限

**步骤 4 — 验证**

```sql
SHOW TABLES;   -- 应看到 20 张表（t_user, t_song, t_artist, t_admin 等）
SELECT * FROM t_admin;  -- 应看到 admin 和 operator 两条记录
```

**整体流程图：**

```
安装 MySQL 程序文件
       ↓
initialize: 创建 data 目录 + 系统表 + 临时密码
       ↓
install:    注册为 Windows 服务
       ↓
net start:  启动 MySQL 服务
       ↓
ALTER USER: 临时密码 → 正式密码
       ↓
init.sql:   创建 20 张业务表（空表）
       ↓
admin-init.sql: 插入管理员账号数据
       ↓
完成！可以启动 Spring Boot 连接数据库了
```

### 4.6 常见问题

| 问题 | 解决方案 |
| ---- | -------- |
| `java: command not found` | 检查 JAVA_HOME 是否设置正确，重启终端 |
| `Unsupported character encoding 'utf8mb4'` | 将 `application-dev.yml` 中的 `characterEncoding` 改为 `UTF-8` |
| `No plugin found for prefix 'spring-boot'` | 确认在 `backend/` 目录下执行命令 |
| `Can't create directory (Permission denied)` | 以管理员身份运行 PowerShell |

| Redis 连接失败 | 确认 Redis 服务已启动：`redis-cli ping` |
| MySQL 服务未注册 | 以管理员身份运行 `.\mysqld.exe --install MySQL84` |
