## 二、可以对接的功能

### 2.1 密码登录 ↔ `/api/v1/auth/login`

| 对接项 | 前端现状 | 后端现状 | 对接方案 |
|--------|----------|----------|----------|
| 请求参数 | `account`（手机号/账号）+ `password` | 方法体空，无 `@RequestBody` | 后端新增 `LoginRequest` DTO，接收 `account` + `password` |
| 密码校验 | 前端模拟错误锁定 | 数据库 `t_user.password`（BCrypt）+ `login_fail_count` + `lock_until` | 后端 Service 层实现：查用户 → 检查锁定 → BCrypt校验 → 更新失败计数/锁定时间 |
| 错误锁定 | 前端 `failCount` + `lockSeconds` + `lockMessage` | 数据库 `login_fail_count` + `lock_until` 字段已就绪 | **改为后端锁定**：5次错锁1分钟，10次错锁10分钟，前端展示后端返回的锁定提示 |
| 成功响应 | 无（未实现） | 返回 `R.ok()` | 后端签发 JWT，返回 `R.ok(LoginResponse)`，含 `accessToken` + `refreshToken` + `expiresIn` |
| Token 存储 | Splash.tsx 读取 `localStorage.auth_token` | JwtTokenProvider 签发 | 登录成功后前端写入 `localStorage.setItem('auth_token', accessToken)` |

**建议的后端 `LoginRequest`：**
```java
public class LoginRequest {
    @NotBlank(message = "账号不能为空")
    private String account;  // 手机号或账号
    @NotBlank(message = "密码不能为空")
    private String password;
}
```

**建议的后端 `LoginResponse`：**
```java
public class LoginResponse {
    private String accessToken;
    private String refreshToken;
    private long expiresIn;       // 秒，与 jwt.expiration 一致
    private String uid;
    private String nickname;
    private String avatar;
}
```

**建议的前端对接代码逻辑：**
```typescript
// 密码登录
const res = await fetch('/api/v1/auth/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ account, password })
})
const data = await res.json()
if (data.code === 200) {
  localStorage.setItem('auth_token', data.data.accessToken)
  localStorage.setItem('refresh_token', data.data.refreshToken)
  navigate('/home', { replace: true })
} else {
  // 展示 data.message（如"密码错误"、"账号已锁定"等）
}
```

### 2.2 注册 ↔ `/api/v1/auth/register`

| 对接项 | 前端现状 | 后端现状 | 对接方案 |
|--------|----------|----------|----------|
| 请求参数 | `regPhone` + `regCode` + `regPassword` + `regConfirmPassword` | 方法体空 | 后端新增 `RegisterRequest` DTO |
| 手机号校验 | 前端限制11位 | 数据库 `t_user.phone` UNIQUE | 后端校验手机号格式 + 是否已注册 |
| 验证码校验 | 前端本地生成（`generateCode`） | 无验证码服务 | **需新增验证码服务**（见 2.3） |
| 密码强度 | 前端 `getPasswordStrength` 指示器 | — | 前端仅做 UI 提示，后端也需校验密码强度 |
| 密码一致性 | 前端 `regConfirmPassword !== regPassword` 校验 | — | 前端校验即可，后端只接收一个 password 字段 |
| 昵称生成 | 无 | `t_user.nickname` NOT NULL | 后端自动生成默认昵称（如"用户XXXX"） |
| UID 生成 | 无 | `t_user.uid` UNIQUE NOT NULL | 后端自动生成唯一 UID |

**建议的后端 `RegisterRequest`：**
```java
public class RegisterRequest {
    @NotBlank @Pattern(regexp = "^1[3-9]\\d{9}$")
    private String phone;
    @NotBlank
    private String code;          // 短信验证码
    @NotBlank @Size(min = 8, max = 16)
    private String password;
}
```

### 2.3 验证码发送 ↔ 需新增 `/api/v1/auth/sms/send`

| 对接项 | 前端现状 | 后端现状 | 对接方案 |
|--------|----------|----------|----------|
| 发送验证码 | `handleGetCode` 本地生成6位随机数 | **无此接口** | **需后端新增** |
| 倒计时 | 前端 `codeCountdown` 60秒倒计时 | — | 前端保持，发送成功后启动倒计时 |
| 验证码过期 | 前端 `codeExpireAt` 5分钟 | — | 后端 Redis 存储验证码，设置5分钟 TTL |
| 验证码展示 | 顶部通知条展示验证码（开发模式） | — | 生产环境去掉通知条，改为短信发送 |
| 防刷 | 无 | — | 后端需限制：同手机号1分钟1次、同IP每天上限 |

**建议的后端接口：**
```
POST /api/v1/auth/sms/send
Body: { "phone": "13800138000" }
Response: R.ok()  // 发送成功
```

**建议的 Redis 存储结构：**
```
Key: sms:code:{phone}        Value: 验证码    TTL: 300s (5分钟)
Key: sms:limit:{phone}       Value: 1         TTL: 60s  (1分钟间隔)
Key: sms:daily:{phone}       Value: 次数       TTL: 86400s (每天重置)
```

> **注意**：短信发送需要接入短信服务商（阿里云SMS、腾讯云SMS等），这是额外成本。开发阶段可先用"控制台输出验证码"替代。

### 2.7 Token 刷新 ↔ `/api/v1/auth/refresh`

| 对接项 | 前端现状 | 后端现状 | 对接方案 |
|--------|----------|----------|----------|
| Token 过期检测 | Splash.tsx 解析 JWT `exp` 字段 | Access Token 2小时，Refresh Token 30天 | 前端需在 API 请求中检测 401，自动调用 refresh |
| 刷新逻辑 | 无 | 方法体空 | 后端接收 refreshToken，验证后签发新 accessToken |

**建议的后端 `RefreshRequest`：**
```java
public class RefreshRequest {
    @NotBlank
    private String refreshToken;
}
```

**建议的前端自动刷新逻辑：**
```typescript
// 统一 HTTP 封装中
if (response.status === 401) {
  const refreshToken = localStorage.getItem('refresh_token')
  if (refreshToken) {
    const refreshRes = await fetch('/api/v1/auth/refresh', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ refreshToken })
    })
    const refreshData = await refreshRes.json()
    if (refreshData.code === 200) {
      localStorage.setItem('auth_token', refreshData.data.accessToken)
      // 重试原请求
    } else {
      // refresh 也失败，跳转登录页
      localStorage.removeItem('auth_token')
      navigate('/login')
    }
  }
}
```

## 三、不能对接的功能（存在缺口）

### 3.1 🔴 短信验证码服务 — 完全缺失

| 缺口 | 说明 |
|------|------|
| 后端无发送接口 | 无 `/api/v1/auth/sms/send` 接口 |
| 后端无校验逻辑 | 无 Redis 存储验证码、无校验逻辑 |
| 无短信服务商接入 | 未集成阿里云/腾讯云 SMS SDK |
| 前端验证码是假的 | `generateCode()` 本地随机生成，顶部通知条展示 |

**影响范围**：验证码登录、注册、重置密码 — 三个模式全部依赖验证码

**解决方案**：
1. **开发阶段**：后端接口返回验证码到响应中（`R.ok(data: { code: "123456" })`），前端展示，不实际发短信
2. **生产阶段**：接入短信服务商，后端发送短信，前端去掉通知条展示

---

### 3.2 🔴 后端 Service/Repository/Entity 层 — 完全缺失

| 缺口 | 说明 |
|------|------|
| 无 Entity 类 | 缺少 `User`、`Admin` 等 JPA 实体类 |
| 无 Repository | 缺少 `UserRepository` 等 JPA Repository |
| 无 Service 层 | 缺少 `AuthService`、`UserService` 等业务逻辑层 |
| Controller 全空壳 | 所有 Controller 方法只返回 `R.ok()`，无业务逻辑 |
